## 검토 기준
각 항목마다 문제가 있는지 판단하고, 근거 위치(파일:줄)를 적는다.

| ID | 기준 | 확인할 것 |
|---|---|---|
| C1 | 결정 작업의 시작 절차와 T02의 자기 의존성 | 결정 자체가 목적인 작업(T00, T02 등)을 절차대로 시작할 수 있는지. 선행 조건이 자기 자신의 산출물을 요구하는 순환이 없는지 |
| C2 | 선행 작업과 선행 결정의 구분 | `선행 결정` 칸에 작업 ID와 결정 ID가 섞여 있지 않은지, 작업 선택 규칙이 둘을 구분해서 판단할 수 있는지 |
| C3 | 학습 확인 대기 상태와 해당 없음 처리 | 학습 확인이 끝나기 전 상태를 표현할 수 있는지, 학습 질문이 없는 작업(문서·설정 등)을 어떻게 처리하는지 정해져 있는지 |
| C4 | 사람의 설계 결정과 AI의 내부 구현 판단 범위 | "결정이 필요하면 멈춘다"는 규칙이 사소한 구현 판단(변수명, 헬퍼 분리 등)까지 막지 않는지. 어디까지가 사람 결정인지 기준이 있는지 |
| C5 | T08 이전의 History 설계 결정과 완료 기준 | T08이 History 저장을 포함하는데, History 구조 결정(D09)이 T08 시작 전에 확정되도록 되어 있는지. T08·T09 완료 기준이 그 결정과 맞는지 |
| C6 | 검증 대상 코드 버전 및 변경 후 재검증 | 검증 결과가 어떤 버전(커밋/작업 트리)을 검증했는지 남는지. 수정 후 재검증이 필수인지, 이전 검증 결과가 무효가 되는 조건이 있는지 |
| C7 | 문서 작업에 맞는 검증 방식 | "테스트를 직접 실행한다" 같은 코드 전용 규칙만 있고 문서 작업의 검증 방법(일관성, 상호 참조, 시나리오 점검 등)이 없는 건 아닌지 |

## 판정 규칙
- 각 기준: `PASS` / `FAIL` / `사람 결정 필요`
- `사람 결정 필요`: 문서만으로 고칠 수 없고 사람이 정책을 정해야 하는 경우. 문서에 `[미정]`으로 기록되어 있으면 전체 판정에서 실패로 세지 않는다.
- 전체 `VERDICT: PASS` 조건: 모든 기준이 `PASS`이거나, `사람 결정 필요`이면서 `[미정]`으로 기록됨
- 기준 밖에서 발견한 문제는 "기타 발견"에 따로 적는다. 심각한 모순이 아니면 판정에 반영하지 않는다.
