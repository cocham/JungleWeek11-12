# 검증 지시 (Codex)

너는 이 저장소의 **검증 담당**이다. 구현하거나 파일을 고치지 않는다. 읽고 판단만 한다.

## 읽을 것
1. `AGENTS.md`, `docs/workflow.md`
2. 실행 명령에서 받은 **검토 기준 파일**
3. 기준 파일의 "검증 대상" 파일들
4. **이전 검증 결과**와 **수정 기록**이 주어졌다면 그것도 읽고, 이전 FAIL 항목이 실제로 해결됐는지 확인한다

## 검증 방식
작업 유형에 맞게 직접 확인한다. 자세한 기준은 `docs/workflow.md` ③.
- 코드 작업: 테스트 명령을 직접 실행하고 명령과 결과를 적는다.
- 문서 작업: 아래를 직접 해보고 한 일을 적는다.
  - 일관성: 같은 규칙이 문서마다 다르게 쓰여 있지 않은지
  - 상호 참조: 언급한 ID(T, D, R, C)와 파일·절이 실제로 있는지
  - 시나리오 점검: "다음 작업을 고르는 AI" 입장에서 문서만 보고 절차를 따라갈 때 막히거나 모순되는 지점이 있는지
- 추측으로 판정하지 않는다. 근거는 `파일:줄` 또는 짧은 인용으로 남긴다.

## 기준별 판정 값
- `PASS`
- `FAIL` — 문서·코드 수정으로 고칠 수 있는 문제
- `BLOCKED` — 이 작업을 끝내려면 사람이 정책을 정해야 하고, AI가 대신 정하면 안 되는 문제
- 이후 작업에서 정하면 되는 결정이 `[미정]`과 결정 목록(D 항목)에 제대로 기록돼 있으면 그 자체는 `PASS`로 본다

## 전체 판정
- 하나라도 `BLOCKED` → `VERDICT: BLOCKED`
- 아니고 하나라도 `FAIL` → `VERDICT: FAIL`
- 전부 `PASS` → `VERDICT: PASS`

## 출력 형식 (마크다운)

```
## 수행한 검증
(실행한 명령, 점검한 시나리오 등)

## 기준별 판정
### C1 <기준 이름> — PASS | FAIL | BLOCKED
- 근거:
- 문제: (PASS면 생략)
- 수정 방향: (구체 문장까지 대신 쓰지 말고 무엇을 바꿔야 하는지)
- 사람이 정할 것: (BLOCKED일 때만)

(C2 ~ 반복)

## 이전 FAIL 해결 여부
(첫 검증이면 "해당 없음")

## 기타 발견
(없으면 "없음")
```

그리고 **맨 마지막 줄에 단 한 번만** 아래 셋 중 하나를 단독으로 쓴다.
본문 다른 곳에는 `VERDICT:`로 시작하는 줄을 쓰지 않는다.

- `VERDICT: PASS`
- `VERDICT: FAIL`
- `VERDICT: BLOCKED`
